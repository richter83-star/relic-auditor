# Relic Auditor v0.4

## Executive assessment

v0.4 makes Technical Truth materially less dependent on name matching. Relic can
now resolve common relative JavaScript/TypeScript imports and aliases, attach
calls to their owning symbols, record simple argument-to-parameter flow, reject
ambiguous project-wide symbol matches, preserve normalized parse results between
runs, and read bounded Git lineage metadata without invoking Git.

This improves the evidence behind workflow and capability classifications. It
does not make Relic a compiler, runtime verifier, security scanner, or proof of
production readiness.

## Added

- Trusted in-process JavaScript/TypeScript tokenizer and balanced-scope
  structural AST
- Import-binding and relative-module resolution
- Caller-owned call edges
- `passes_data`, `reads_from`, and `writes_to` graph edges
- Content-addressed persistent parse cache
- Static Git HEAD, branch, remote, packed-ref, and worktree inspection
- Scan-boundary refusal for external worktree Git directories
- Evidence-backed framework surfaces for React, Next.js, Express, Fastify,
  FastAPI, Flask, Django, BullMQ, Celery, Prisma, and SQLAlchemy
- UI-screen and mock-data detection
- Stub-aware capability classification
- Explicit data-flow graph limits
- Deterministic skeptical executive conclusions

## Known false-positive risks

- Framework convention patterns may associate a surface with the wrong nearby
  symbol.
- A statically connected path may be disabled by runtime configuration.
- A simple shared queue name may connect producer and consumer variants that are
  not deployed together.
- `reads_from` and `writes_to` are naming-based structural indicators.

## Known false-negative risks

- Dynamic imports, re-export chains, dependency injection, decorators, factory
  registration, reflection, metaprogramming, and generated code.
- Calls through objects, higher-order functions, callbacks, event buses, and
  complex alias chains.
- Cross-language or package-level boundaries.
- Runtime route composition and authorization policy behavior.

## Remaining architectural debt

- JavaScript/TypeScript parsing is not compiler-grade and has no type checker.
- Data flow is direct identifier mapping, not interprocedural taint analysis.
- Git lineage does not inspect object history, merge bases, or remote state.
- The persistent cache is a deterministic JSON store, not a transactional
  multi-process cache.
- Framework detection and workflow rules still live in the central analyzer and
  should move behind formal adapter registries as coverage expands.

## Recommended v0.5

Add optional trusted parser packs behind the existing adapter interface,
starting with Tree-sitter when distributable parser binaries are available.
Then add type-aware resolution for Python and TypeScript, framework-specific
registration adapters, explicit authorization-flow modeling, and incremental
graph construction. Keep deterministic edges authoritative and model-assisted
interpretation bounded to redacted graph summaries.
