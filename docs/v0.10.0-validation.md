# v0.10.0 validation contract

The release candidate must pass the focused 47-test Build Pack slice, the full
repository suite without deselection, the extracted frozen-source suite, Ruff,
formatting, mypy for the Build Pack domain, compileall, dependency consistency,
wheel/sdist builds, offline Free, Pro non-leakage, deterministic Premium, fake
provider behavior, clean-wheel CLI and offscreen GUI smoke tests.

A representative Build Pack must reproduce, validate its canonical JSON,
evidence, manifest, approval, assets and checksums, contain no secrets or local
absolute paths, and prove its scan target remained byte-for-byte unchanged.

The Windows workflow must hash-pin the frozen source and run both repository and
contained suites in full. Installer build, clean install/uninstall, and signing
status remain pending until the user separately approves remote publication and
workflow execution.
