# Relic Auditor 0.12.0 release candidate

v0.12.0 is the production-foundation milestone between the v0.11 Assisted
Build Supervisor and the v0.13 Revival Loop beta.

## What changed

- Production execution accepts only Relic path-confined writes and the exact
  Codex ephemeral `workspace-write` profile. Altered Codex commands, generic
  native processes, and the Claude builder preview fail closed.
- Cancelling a running builder terminates its process tree, restores the
  pre-action checkpoint, and records the cancelled action in the signed
  session history.
- Stable update manifests use a separate pinned Ed25519 trust root. Unsigned,
  legacy, unprovisioned, unknown-key, and tampered manifests cannot reach the
  download stage.
- Signed license tokens can refresh their offline window without storing or
  resending the original license key.
- Claude setup and runtime truth remain separate. A timeout or failure is
  persisted and cannot be overwritten by a later “configured” setup check.
- The complete five-step product path remains visible, table rows and column
  floors are larger, and every evidence grid points to its full-record inspector.

## Honest release limits

- The repository contains no production update or licensing public key yet.
  Release builds therefore fail closed until external keys are provisioned.
- In-app update installation also requires a trusted Dracanus AI Authenticode
  certificate and permanent public hosting.
- Claude assisted-build remains blocked pending an approved commercial model
  and a production isolation boundary.
- A candidate remains local and review-required. There is no automatic publish,
  deployment, payment, message, tag, or GitHub Release action.
- v0.13 still needs the closed scan → build → verification → re-audit loop.
