# Relic Auditor 0.10.2 release notes

v0.10.2 adds the first-party Windows updater foundation and makes repeat
installation an explicit in-place upgrade path.

## A visible update path

- Installed builds check the stable channel at most once every 24 hours.
- Failed checks retry no sooner than six hours and leave Relic fully usable
  offline.
- **Check updates** is always visible beside the installed version.
- An available update uses a three-step flow: compare versions, download and
  verify, then install.
- Relic never silently installs an update and never interrupts an active audit.

## Fail-closed verification

Update manifests are bounded, strict JSON fetched only over HTTPS. Installer
URLs and redirects must remain HTTPS, filenames cannot escape the update
directory, downloads are size bounded and written through a `.part` file, and
the final file must exactly match the declared byte count and SHA-256 digest.
Superseded Relic installer downloads are removed from the private update cache,
so versions do not accumulate there.

Before an Install button is enabled, Windows must report a valid Authenticode
signature whose certificate simple name exactly matches the publisher pinned
in the application (`Dracanus AI`). Relic verifies the digest and publisher again
immediately before launching the installer with a fixed argument list and
`shell=False`. A changed, unsigned, or differently signed installer is deleted
or blocked.

## In-place upgrade behavior

The installer retains the same Inno Setup `AppId`, per-user install directory,
shortcuts, and uninstall registration used by v0.10.0 and v0.10.1. It refreshes
the managed PyInstaller runtime directories before copying the new payload so
renamed dependencies do not accumulate. Configuration under
`%APPDATA%\Relic Auditor` and reports under Documents remain untouched.

## Distribution prerequisite

The updater code is complete, but automatic installation remains intentionally
blocked for unsigned builds. Production activation requires both a permanent
public `downloads/stable.json` endpoint and a trusted Dracanus AI code-signing
certificate in the Windows workflow. GitHub Actions artifacts are not suitable
as the update endpoint because they expire and the repository is private.

No Git tag or GitHub Release is required or created by this feature.
