# Relic Auditor 0.10.1 release notes

v0.10.1 is a focused usability and provider-state correction based on the
first installed v0.10.0 audit.

## Provider state is now truthful

- Installation, authentication, and subscription detection report
  `CLAUDE: CONFIGURED`; they no longer claim a request is ready or operational.
- A live advisory request reports `CLAUDE: RUNNING`.
- Only a completed advisory request reports `CLAUDE: OPERATIONAL`.
- Timeouts and other request failures replace the global and sidebar badges
  with `TIMED OUT` or `FAILED` and state that deterministic results remain
  complete.
- Opus with high effort now carries an explicit timeout warning; Sonnet with
  medium effort remains the recommended starting point.

## The product now shows the next step

The three-section Scan, Results, and Reports shell remains intact. A persistent
five-step guide now moves through folder selection, audit start, active scan,
results review, and the final prepare/export outcome. Technical details also
state a recommended review order instead of presenting nine peer tabs without
direction.

## Evidence is readable

- Technical columns retain a font-derived readable floor. Narrow views use an
  honest horizontal scrollbar instead of reducing cells to ellipses.
- Narrative columns consume available space.
- Rows have greater font-derived vertical padding.
- Every technical results grid includes a persistent structured-record
  inspector.
- Collections of evidence records are summarized in cells and shown in full in
  tooltips and the inspector rather than as raw Python dictionaries.

## Gated actions explain themselves

When a leading opportunity exists but Build Pack preparation is unavailable,
the disabled action remains visible with the evidence or entitlement reason.

This patch does not weaken Relic's local-first, read-only, no-execution boundary
and does not create or authorize a Git tag or GitHub Release.
