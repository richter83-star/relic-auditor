# Relic Auditor v0.7.0

v0.7 adds an optional advisory LLM layer without changing Relic's deterministic
or read-only core.

## Authentication

- API-key profiles read credentials from a named environment variable.
- OAuth profiles use Authorization Code + PKCE, random state validation, a
  loopback callback, refresh tokens, and the operating system credential vault.
- Non-secret endpoint/model/profile metadata is stored separately from
  credentials.
- Remote HTTP endpoints are rejected; unencrypted HTTP is allowed only for
  localhost development.

OAuth is standards-based rather than tied to a consumer AI subscription. The
configured provider must issue a public desktop client ID and authorize its
access token for the inference API.

## Supported inference protocols

- OpenAI Responses API
- OpenAI-compatible Chat Completions API
- Anthropic Messages API

## Reasoning boundary

The model receives only a size-bounded, recursively redacted summary of
Capability Acquisition evidence. It does not receive direct filesystem access,
the raw estate, API keys, OAuth tokens, or action tools. Repository strings are
delimited as untrusted data.

The sidecar produces `llm_reasoning_report.md` and `llm_reasoning.json`.
Deterministic acquisition reports are written independently and remain
available when a provider is offline, rejects authentication, times out, or
returns malformed output.

## Integration

Optional reasoning is available from:

- `relic acquire ... --llm-profile PROFILE`
- `relic audit ... --llm-profile PROFILE`
- `relic monitor ... --llm-profile PROFILE`
- The dashboard's **Use optional LLM reasoning** control

`--llm-required` returns a distinct failure status after deterministic reports
are written when advisory reasoning is mandatory for an outer workflow.

## Safety

The LLM layer cannot execute scanned code, install dependencies, extract onto
the target, change files, delete, deploy, approve actions, provision resources,
or expand authority.
