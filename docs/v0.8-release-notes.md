# Relic Auditor v0.8 release notes

## Claude Code subscription provider (`claude-code`)

- New reasoning protocol `claude-code` with authentication mode
  `claude-subscription`: the optional advisory layer can run through the
  locally installed Claude Code CLI, reusing the user's existing Claude.ai
  (Max/Pro) OAuth session. No Anthropic API key is requested or used.
- Strict subscription-only billing boundary: before every invocation Relic
  verifies via `claude auth status` that a logged-in Claude.ai subscription
  session exists, rejects obvious Console/API-key logins, and removes
  `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, and `ANTHROPIC_BASE_URL` from
  the child process only. Usage remains subject to Anthropic plan limits.
- Hardened invocation: argument-list subprocess (never `shell=True`), prompt
  through stdin, empty temporary working directory, bounded input and output,
  configurable timeout, `--max-turns 1`, `--no-session-persistence`,
  `--safe-mode`, `--tools ""`, `--strict-mcp-config`, and a required JSON
  output schema validated before use.
- Structured advisory output: `executive_summary`, `reusable_capabilities`,
  `missing_capabilities`, `contradictions`, `recommended_build_path`,
  `risk_notes`, `evidence_citations` (validated against the deterministic
  evidence envelope), and `confidence_notes`. All conclusions stay advisory.
- CLI: `relic llm add NAME --protocol claude-code --model sonnet --auth
  claude-subscription [--effort low|medium|high]`, plus `llm login` (launches
  the official `claude auth login`), `llm status` (safe fields only), and
  `llm list`.
- Dashboard: first-class "Claude Code / Claude Max (subscription)" provider
  selection with model alias, effort level, installation/authentication
  checks, login launcher, and sanitized failure reporting — clearly separated
  from API-key billing and generic OAuth profiles.
- Reports: `llm_reasoning_report.md` / `llm_reasoning.json` now carry safe
  provider metadata (protocol, authentication, model, effort, truncation flag,
  evidence record count, success flag, sanitized error, deterministic-reports
  preserved). Tokens, emails, organization IDs, raw auth output, and
  credential paths are never recorded.

## Billing-guard hardening

Findings from an adversarial review of the new provider, all addressed:

- **API-billing evidence outranks an OAuth-looking method string.** A session
  can report both markers at once (a Claude.ai login shadowed by an exported
  API key, which the real CLI signals with `apiKeySource` and a null
  `subscriptionType`). That is now classified `api-key` and rejected, instead
  of being treated as a subscription.
- **Entitlements use an allow-list.** Only known-active plans count; `expired`,
  `free`, `lapsed`, and unrecognized values fail closed. Object-shaped plans
  must carry an explicit active flag. A null or empty value means "this build
  did not report the field" and falls back to the verified login.
- **Third-party billing redirects are stripped** alongside the API key:
  Bedrock/Vertex routing variables would otherwise send the call to a metered
  third-party account.
- **`loggedIn` is parsed strictly**, so the string `"false"` no longer reads as
  logged in.
- **Claude Code stderr is never forwarded.** Only the exit status and a coarse
  category reach reports; raw stderr can carry emails, organization IDs, and
  credential paths.
- **Every invocation is checked at call time** (`_assert_hardened`) for the
  full hardening flag set and an empty tool list, so a future edit that drops
  `--tools ""`, `--safe-mode`, or `--strict-mcp-config` fails loudly instead of
  silently granting Claude Code tools.
- **All three subprocess calls** (`auth status`, `--version`, and the reasoning
  call) run from an isolated empty temporary directory, never Relic's own
  working directory.
- **Citations are verified against deterministic anchors.** Natural formats
  such as `gov.py:1 — "def approval_queue():"` are accepted because they name
  a real observed path and capability, while a fabricated file is dropped with
  a warning.
- **Envelope bounding is reported, not silent.** Omitting candidates or
  per-candidate evidence now sets `prompt_truncated` and emits warnings.

## Unchanged guarantees

- The deterministic scanner works without Claude Code installed.
- CLI auditing, dashboard, Technical Truth, Product Resurrection, Capability
  Acquisition, Relic Monitor, API-key providers, standards-based OAuth
  profiles, secret redaction, and deterministic fallback reports are all
  preserved from v0.7.
- Provider failures never remove or suppress deterministic reports.
