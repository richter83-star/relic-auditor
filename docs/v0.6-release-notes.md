# Relic Auditor v0.6.0

v0.6 introduces deterministic Capability Acquisition Mode and Relic Monitor
without changing Relic Auditor's local-first, read-only safety contract.

## Capability Acquisition Mode

`relic acquire <target>` accepts a loose file, folder, or ZIP archive and
detects static evidence for:

- Orchestrator
- Goal Registry
- Autonomy Loop
- Governance Boundary
- Approval Queue
- Audit Log
- Self-Improvement Proposal
- Resource Request

The engine uses explicit weighted signals. Every item records whether content
was inspected, its matches, confidence, evidence lines, context classification,
and limitations. Source candidates are ranked separately from documentary,
example, configuration, and test evidence.

Outputs:

- `capability_acquisition_report.md`
- `capability_acquisition_inventory.json`
- `capability_acquisition_candidates.json`
- `capability_acquisition_gaps.json`

The suggested build sequence is governance-first: authority boundary, audit
log, approval queue, goal registry, orchestrator, bounded autonomy loop,
review-only improvement proposal, and externally approved resource request.

## Relic Monitor

`relic monitor <inbox>` polls one local inbox without third-party dependencies.
A drop becomes eligible only after its recursively computed size, file count,
and newest modification time remain stable for the configured debounce period.
The same unchanged drop is processed once; a changed fingerprint becomes
eligible again after another stability window.

Monitor reports are always required to live outside the inbox. Partial download
suffixes, hidden entries, symlinks, junk, VCS metadata, dependency trees, and
caches are ignored.

## ZIP and report safety

ZIPs remain virtual: Relic does not extract them onto the target. Member paths,
symlinks, encryption, expansion size, member count, and compression ratio are
validated before content reads. Archive junk and dependency members are now
skipped from the inventory.

All canonical JSON and Markdown report writers now apply recursive secret
redaction at the output boundary.

## Dashboard

The optional native dashboard adds a Capability Acquisition analysis mode and a
searchable Acquisition candidate tab. Scans remain in memory until the user
chooses an external report folder.

## Compatibility

- Python 3.11 or newer
- No new base dependencies
- PySide6 remains optional under `.[gui]`
- Existing `relic audit` behavior and v0.4/v0.5 analysis modes remain available
