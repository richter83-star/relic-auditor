# Relic Auditor 1.0.1

v1.0.1 is the public reconciliation release that reunifies Relic Auditor's validated v0.12 production foundation with the later Resurrection and Technical Truth work that had developed on a disconnected repository history.

Public release: https://github.com/richter83-star/relic-auditor/releases/tag/v1.0.1

## What changed

- Restored one coherent lineage containing Build Packs, licensing, the Assisted Build Supervisor, updater/trust roots, provider health checks, desktop packaging, and later analysis improvements.
- Added standalone `relic resurrect <target>` dispatch without replacing or weakening the existing v0.12 CLI command surface.
- Ported deterministic Resurrection extraction and salvageability gating, including a forced `TOSS_IT` path for codebases without a substantive connected core.
- Corrected Resurrection's configured-LLM integration to use the v0.12 provider contract with bounded input/output and timeouts.
- Hardened LLM result validation, citation requirements, evidence-ID grounding, path/symbol grounding, confidence bounds, and secret redaction.
- Replaced the old “real-time market” wording with an explicit offline heuristic market-context provider. v1.0.1 does not claim live market research.
- Ported four Technical Truth correctness fixes: bare-raise stub detection, call-argument ordering, Next.js App Router reconstruction, and route-suffix collision hardening.
- Promoted package, CLI, Windows resources, manifest, Inno Setup, source freezing, and installer lifecycle metadata coherently to 1.0.1.
- Made the installer frozen-source version check CRLF/LF-safe after Windows validation exposed the earlier multiline-regex defect.
- Reconciled the disconnected default-branch history without deleting either history. The prior line remains at `archive/disconnected-main-v1.0.0`.

## Preserved safety boundaries

- Scanned targets are never imported, installed, executed, modified, moved, renamed, or deleted.
- Build Packs copy only explicitly approved, hash-verified eligible assets into a separate managed destination.
- Assisted Build actions are approval-gated and confined to managed workspaces and supported provider boundaries.
- Secrets and prompt-like repository text are treated as untrusted data.
- Optional LLM reasoning is bounded and advisory; deterministic evidence remains authoritative.
- Update installation remains fail-closed unless manifest, hash/size, and Authenticode trust requirements are satisfied.

## Known limits

- The public Windows installer is not Authenticode-signed. Windows may display an unknown-publisher warning.
- Automatic updater installation remains blocked by design until trusted signing and a signed stable manifest are provisioned.
- Production update/licensing trust material and permanent stable hosting remain external infrastructure tasks.
- Market context is offline/static heuristic context, not live research.
- `audit --resurrection` is not provided in v1.0.1; use `relic resurrect`.
- Repository branch protection requires GitHub repository-admin configuration and is not exposed by the connected automation interface.
